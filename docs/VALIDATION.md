# 검증 기록

2026-10-21의 구현과 실제 Firebase 프로젝트에서 확인한 결과다. 개인 원본, 비밀번호, API 키와 화면 캡처는 저장소에 넣지 않는다.

- 날짜·검색·반복·백업 검사 22개 통과. 날짜를 옮긴 반복 일정의 중복, 첫 일정 삭제, 백업 복구·재가져오기와 기존 변경 보호를 포함한다.
- Firestore 에뮬레이터 보안 검사 10개 통과. 계정 간 접근, 관리자 승격, 자기 계정 중지와 비활성 계정의 접근을 검사한다.
- 원본 3,380개와 과거 반복 일정 보충분 7개를 이관했다. 서버에서 다시 내보낸 백업과 원본의 62,824개 필드를 대조해 모두 일치했다. 과거·미래 15개 기간의 반복 일정도 원본 서비스 결과와 대조했다.
- 실제 브라우저의 폭 320·390·768·1024·1440px에서 화면을 확인했다. 모바일 요일 전환·메뉴·메모 편집·저장, 태블릿 일정 추가, 검색, 휴지통 복원과 새로고침 후 유지를 확인했다. 가로 화면 넘침이 없고 좁은 태블릿은 메뉴를 접으며 4열로 표시한다.
- 인터넷을 끊고 추가한 일정이 재연결 후 서버에 저장됨을 확인했다. 관리자에서 계정을 중지한 뒤 해당 계정의 실제 접근 차단과 재허용을 확인했다.
- 이전 이관 기록이 포함된 백업을 실제 DB에 복구하고 다시 가져왔다. 같은 자료 8개를 건너뛰어 중복 저장하지 않았다.
- 로컬 배포용 미리보기에서 처음 로그인 후 전체 자료 표시는 약 2.9초, 캐시가 있는 새로고침 후 표시는 약 0.9초였다. 인터넷 호스팅 성능 측정과는 구분한다.

배포는 별도의 승인과 실제 게시 주소의 확인이 필요하다. 검사 통과나 데이터 이관만으로 게시 완료를 뜻하지 않는다.
