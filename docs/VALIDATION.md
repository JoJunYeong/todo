# 검증 기록

2026-10-21의 구현과 실제 Firebase 프로젝트에서 확인한 결과다. 개인 원본, 비밀번호, API 키와 화면 캡처는 저장소에 넣지 않는다.

## 가독성 개선 게시

기본 접힘 사이드바, 간결한 상단, 큰 할 일 글자와 선명한 완료 상태를 적용한 소스 `23480b6`을 Discord Yes 승인 후 게시했다. 게시 파일 커밋은 `630c882`, Pages 전용 배포 실행은 `39554578918`이며 성공했다.

- 날짜·검색·반복·백업 검사 22개와 배포 빌드가 통과했다.
- 배포용 미리보기와 실제 게시 주소 모두에서 메뉴·키보드·검색·메모·요일 전환·주 이동·화면 크기 검증 22항목이 통과했다. 폭 320·390·768·1024·1440px에서 가로 넘침 없이 기본 접힘을 확인했다.
- 실제 주소의 HTML·CSS·JavaScript·아이콘 7개가 승인본과 크기·SHA-256까지 일치했다. 배포 묶음 SHA-256은 `3129eae56f40d30109b823a5dfc16ba8c7aa04d410b997d46577cc1adefea664`다.
- 일반 Actions 검사는 계정 결제 잠금으로 작업이 시작되지 않았다. 로컬 검사와 Pages 전용 게시 성공을 구분해 확인했다. 결제 설정은 변경하지 않았다.

참고 사례와 전후 비교는 [가독성 검토](UX_REVIEW.md)에 있다.

## 최초 구축 및 이관 검증

- 날짜·검색·반복·백업 검사 22개 통과. 날짜를 옮긴 반복 일정의 중복, 첫 일정 삭제, 백업 복구·재가져오기와 기존 변경 보호를 포함한다.
- Firestore 에뮬레이터 보안 검사 10개 통과. 계정 간 접근, 관리자 승격, 자기 계정 중지와 비활성 계정의 접근을 검사한다.
- 원본 3,380개와 과거 반복 일정 보충분 7개를 이관했다. 서버에서 다시 내보낸 백업과 원본의 62,824개 필드를 대조해 모두 일치했다. 과거·미래 15개 기간의 반복 일정도 원본 서비스 결과와 대조했다.
- 실제 브라우저의 폭 320·390·768·1024·1440px에서 화면을 확인했다. 모바일 요일 전환·메뉴·메모 편집·저장, 태블릿 일정 추가, 검색, 휴지통 복원과 새로고침 후 유지를 확인했다. 가로 화면 넘침이 없고 좁은 태블릿은 메뉴를 접으며 4열로 표시한다.
- 인터넷을 끊고 추가한 일정이 재연결 후 서버에 저장됨을 확인했다. 관리자에서 계정을 중지한 뒤 해당 계정의 실제 접근 차단과 재허용을 확인했다.
- 이전 이관 기록이 포함된 백업을 실제 DB에 복구하고 다시 가져왔다. 같은 자료 8개를 건너뛰어 중복 저장하지 않았다.
- 로컬 배포용 미리보기에서 처음 로그인 후 전체 자료 표시는 약 2.9초, 캐시가 있는 새로고침 후 표시는 약 0.9초였다. 인터넷 호스팅 성능 측정과는 구분한다.

Discord의 해당 커밋·파일 묶음 Yes 승인을 확인한 후 <https://jojunyeong.github.io/todo/>에 게시했다. 소스 커밋은 `eccad50`, 게시 파일 커밋은 `6b645f2`다. 실제 주소의 HTML·CSS·JavaScript·아이콘 7개가 승인한 로컬 파일과 SHA-256까지 일치했다. 일반 Actions는 결제 문제로 시작되지 않았으며, Pages 전용 배포 실행 `39545689633`은 성공했다.

게시 주소에서도 지정 계정 로그인, 메모 검색·열람, 휴대폰·태블릿 화면을 확인했다. 별도 테스트 계정으로 일정·메모·체크리스트를 저장하고 새로고침 후 다시 검색·열어 값이 유지됨을 확인했다. 관리자와 일반 계정 모두 다른 계정의 메모 조회가 실제 DB에서 거부됐다.
